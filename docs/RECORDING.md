# 框选录制（feature/region-recording）

入口：设置 → 录制，或自行绑定的录制快捷键。识别页和通用设置不放录制入口。

录制子页先选择视频、GIF或仅音频，再开始录制；常用区显示当前类型的帧率、音源、鼠标及保存位置。FFmpeg路径、按类型分别保存的目录、具体音源设备和编码选项收在默认折叠的「高级设置」中。快捷录制浮窗只放开始、停止及跳转设置的按钮。

## 使用

- 安装 FFmpeg 并加入 PATH，或在录制设置中填写 ffmpeg.exe 的完整路径。本程序不分发 FFmpeg。
- 可选择框选 GIF、框选视频（MP4 / H.264）及单独录音（M4A / AAC）。GIF 不包含声音。
- 视频可选择无声、系统输出声音、麦克风、两者混合；可分别指定麦克风和输出设备，默认跟随默认设备。当前音源支持单声道和双声道，其他声道数会明确报错。
- 首次未设置目录时打开目录选择器；视频、GIF、音频目录分别保存。也可使用应用目录下 recordings/video、recordings/gif、recordings/audio。
- 框选支持虚拟桌面、跨屏和不同 DPI；单击可选择顶层窗口。录制入口使用独立、不激活窗口的透明边框层，不调用截图选择器、不截取桌面快照、不生成缩略预览；框选期间底层画面继续更新且不改变目标窗口焦点。仅在明确框选期间临时接管鼠标选择，右键或Esc取消；不使用子元素识别或离屏整窗渲染。
- 每次开始创建独立文件；正在录制时通过「再录一个选区」打开面板，可增加其他区域。每个会话有独立停止按钮。
- 竖向控制窗优先放在选区右侧，放不下改左侧，最后限制在可见工作区内。边框、角落计时/分辨率、控制窗排除出录制；正式录制期间边框鼠标穿透。Windows 10 2004 或更新版本支持完整的捕获排除能力。
- 设置 → 全局热键中可绑定「录视频/停止最近视频」「录GIF/停止最近GIF」「录音/停止最近录音」「录制面板」「停止全部」。默认不添加新快捷键，避免占用游戏按键；面板始终可新开同类会话。Esc 在录制控制窗获得焦点时停止该会话，不设置全局 Esc 拦截。
- 停止后可使用系统关联应用预览文件，或打开保存目录。关闭程序会尝试完成正在进行的编码；编码异常时保留 .partial 文件并报告其路径。

## 性能与限制

视频帧率可设1–360，0表示读取选区覆盖面积最大的显示器刷新率，读取失败回退60。GIF默认15，可设1–60。当前画面输入使用FFmpeg gdigrab，帧率是采集目标值，不是逐刷新事件同步；实际速度取决于区域大小、并行会话数和编码器。软件编码默认libx264/veryfast/zerolatency，也可手动选择NVIDIA/Intel/AMD H.264编码器，硬件不支持时报告FFmpeg错误，不悄悄改变配置。独占全屏/受保护画面需单独验证。

内存优先用于有界缓冲，后台持续编码写盘，不在停止后才编码所有原始帧。FFmpeg输入实时缓冲参数为视频32MiB、PCM音频1MiB；这些不等于进程总内存上限，编码器、滤镜及系统还会分配内存。WASAPI每音源缓冲500ms，音频通过本用户专用命名管道送到FFmpeg，静音时继续发送静音以保持时长。不同硬件时钟的长时同步仍需实机验证。

高级参数允许编码质量相关选项，例如 `-crf 18 -preset fast`；不接受新增输入、输出路径或覆盖文件等选项。含空格的值使用双引号。

- 命令启动修复先提交在main，之后快进同步到录制分支。实际启动普通PowerShell子进程验证其非管理员令牌；尚需用户在管理员启动软件的实际场景复核。
- 自动测试包含负桌面坐标、输入缓冲/高级参数、录制窗口，以及合成素材的GIF、视频、音频与音视频合录；原滚动截图测试继续通过。
- 最终联合回归83项通过，含普通停止时PCM管道关闭不误报、异常关闭仍报错、独立录制设置页、主分支贴图尺寸修复及原快捷键/滚动截图。管道测试发送合成静音，不采集用户音源；受限沙箱禁止本用户管道连接时需在普通桌面权限下运行。
- 原生实时选择器对照（tests/Kscan.Record.NativeChecks）：框选期间底层测试窗口持续变色并增加204帧，focusLost=False，返回310×100选区。该窗口未暂停渲染，选区层未改变前台焦点。
- 修复正常停止后FFmpeg关闭PCM管道导致误报录音失败，以及已保存文件的预览/目录打开失败被误报为录制失败。Shell打开操作显式使用应用目录，避免继承WindowsApps等不可用工作目录。
- 本机FFmpeg为2026-10-25构建。该版thread_queue_size仅用于输出队列；已避免将其错误放到输入前。

- 本机测试时只有一块可见显示器；跨屏混合DPI、多个并行会话、高刷新率、长时间录制及麦克风混合仍需用户硬件验证，未宣称全场景满帧。
